# BEACON-XAI: полный эталон чувствительности модели на исходных сигналах PAMAP2

Дата: 20.11.2026. Исследовательская ветка `feature/contrastive-q16-20261119`.

## Что проверяли

Для каждого исходного (без искусственных вставок) окна PAMAP2 вычисляли полный набор из 36 изменений от интерполяционной нейтрализации каждого компонента. Эталон — упорядочение этих 36 компонентов по абсолютному изменению разности двух наибольших выходных оценок одного и того же классификатора. Это **внутренняя эталонная чувствительность модели**, а не причинная значимость и не экспертное объяснение.

Сравнивали совпадение трёх первых компонентов (top-3 overlap, от 0 до 1) при едином операторе вмешательства. Q0 — статистическая оценка без дополнительных вызовов; Q16 — 16 настоящих модельных проверок; Q36 — только офлайновый эталон, не включённый в эксплуатационный бюджет. Классификатор: ExtraTrees (120 деревьев) на признаках `_anfis_features`. Протокол: обучение и нормализация только на других участниках, пять внешних разбиений, 640 исходных окон всего. Seed 57.

## Предварительный итог: девять участников (макросреднее)

| Метод | Дополнительные вызовы | Совпадение топ-3 с Q36 |
| --- | ---: | ---: |
| Статистический `adaptive_v2_cheap_q0` | 0 | 19,48% |
| Случайный выбор 16 компонентов | 16 | 40,30% |
| Разнообразие по датчикам | 16 | 60,91% |
| Разнообразие по времени | 16 | 62,42% |
| Исходный `adaptive_v2_original_q16` | 16 | **63,86%** |

Единица макроусреднения — участник, а не окно и не повтор запуска. В 516 из 640 окон граница между 3-м и 4-м по эталонному отклику компонентами была больше `1e-6`; на этом подмножестве среднее по участникам совпадение исходного Q16 равно 65,84%.

## Решение и границы применимости

- **Не заменять** исходный отбор временем/датчиками на основании этих результатов. Он остаётся лучшим из проверенных по макросреднему.
- Воспроизведение полного Q36 при Q16 не делает объяснение истинным: сам оператор нейтрализации может создавать неестественные комбинации датчиков; верность модели и физическая причинность — разные задачи.
- Окна одного участника перекрываются, а обучающие группы внешних разбиений частично пересекаются. Нет независимого статистического вывода о популяции или превосходстве на других моделях.
- Нужны повторения на raw-input модели и на другом корпусе, сравнение затрат Q8/Q16/Q32 с Q36, замеры памяти и времени на целевом TinyML-устройстве.

Источник результатов: [GitHub Actions — полный перебор Q36, 5 успешных заданий](https://github.com/fims9000/BeaconXAI/actions/runs/44646579404), проверенный код `e03527eca2e4e7a38326aa8569971e14fc55a274`. Артефакты каждой пары участников содержат `manifest.json`, `per_sample.csv`, `per_subject.csv` и `reference_windows.csv` с контрольными суммами исходного NPZ в манифесте.

## Независимое повторение на UCI HAR (20.11.2026)

Для исключения зависимости выводов от одного корпуса выполнен тот же протокол на **UCI HAR**: официальное разделение 21/9 участников на обучение и тестирование, окна 128×9 инерциальных каналов, группы body acceleration / body gyroscope / total acceleration. Данные загружены через `scripts/preprocess_uci_har_for_q36.py` с валидацией идентификаторов участников. Исходные сигналы не изменяются; полный эталон Q36 — абсолютное изменение интерполяционной разности двух наибольших оценок модели, а **не причинное объяснение**.

| Модель | Тестовых участников | Окон | Q0 | Q8 | Q16 | Q32 | Равномерный Q16 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| ExtraTrees на вычисленных признаках | 9 | 180 | 17,78% | 39,44% | 63,15% | 84,63% | 39,81% |
| MLP (32 скрытых нейрона, исходный временной ряд) | 9 | 90 | 18,15% | 41,85% | 73,70% | 98,52% | 40,00% |

Все значения — **макросреднее по участникам совпадения top-3 с полным Q36**, а не hit@3 искусственно вставленного участка. Каждая дополнительная модельная проверка Q8/Q16/Q32 **выполнялась реально**, а не реконструировалась из Q36. Для сопоставления честно учитываются размеры выборок: ExtraTrees — 20 окон на участника, MLP — 10. Классы тестирования не участвовали в выборе кандидатов.

У ExtraTrees лишь **102/180** исходных окон имели расстояние между третьим и четвёртым эталонными эффектами больше `1e-6`. На этом подмножестве макросреднее совпадение BEACON составило: Q0 **20,64%**, Q8 **40,38%**, Q16 **62,81%**, Q32 **95,24%**. У MLP все **90/90** эталонных троек прошли эту диагностическую границу (для неё: Q16 73,70%, Q32 98,52%).

На MLP временно-разнообразный Q16 дал 74,44% против исходного Q16 73,70%, но на ExtraTrees он уступил: 62,22% против 63,15%. Поэтому нет оснований менять селектор по умолчанию.

**Подтверждённые запуски:** [UCI HAR full-Q36, обе архитектуры успешно](https://github.com/fims9000/BeaconXAI/actions/runs/44648520596). Артефакты `uci-har-qgrid-extratrees` и `uci-har-qgrid-raw_mlp` содержат `per_subject.csv`, `per_sample.csv`, `summary.csv`, `reference_windows.csv` и `manifest.json`. Код: `scripts/preprocess_uci_har_for_q36.py`, `scripts/run_full_sensitivity_reference.py`, workflow `.github/workflows/uci_har_sensitivity.yml`.

### Практический вывод

1. Исходный BEACON при Q16 на двух наборах данных и двух моделях воспроизводит существенную часть **собственного полного отклика модели** при 16/36 дополнительных проверках (сокращение числа дополнительных проверок на 55,6% относительно Q36).
2. При Q32 совпадение с полным перебором заметно выше, но цена вдвое больше Q16. Q8 экономнее, но сильно хуже по указанной метрике.
3. Физическая применимость к TinyML пока **не установлена**. Время GitHub runner не заменяет потребление RAM, энергии, latency и прошивочную реализацию на микроконтроллере. Полный перебор той же нейтрализацией — внутренний суррогатный эталон, а не физическая причинность.
4. Независимый корпус тоже не устраняет смещение общей методики: на обоих наборах все методы сравниваются с Q36 по одному виду искусственной нейтрализации. Следующий независимый контроль — иной оператор вмешательства и реальная приборная оценка.

## Матчированный бюджетный эксперимент PAMAP2 Q0/Q8/Q16/Q32 (20.11.2026)

В отличие от раннего исследования фиксированного Q16 проведён **непосредственный** прогон каждого значения Q на одних и тех же исходных окнах внутри внешнего разбиения. Эталон Q36 сформирован отдельно; модель, оператор, исходное окно и протокол разделения участников постоянны при сравнении Q. Результаты ниже не следует численно отождествлять с более ранним прогоном на 640 окнах: здесь выбраны другие окна и меньшее количество образцов.

| Бюджет | ExtraTrees: 9 участников, 320 окон | Raw-input MLP: 4 участника, 64 окна |
| --- | ---: | ---: |
| Q0 | 19,39% | 24,48% |
| Q8 | 39,76% | 42,71% |
| Q16 | 64,24% | 67,19% |
| Q32 | 91,78% | 94,79% |

Вычислено **макросреднее по участникам** top-3-overlap относительно полного Q36, а не среднее по зависимым перекрывающимся окнам. В каждом разбиении Q8/Q16/Q32 был действительно выполнен на модели, с точным учётом числа вмешательств. Для сравнения, равномерное Q16 дало 39,47% у ExtraTrees и 40,10% у MLP.

**Прирост монотонен по всем участникам**, отдельно для ExtraTrees 9/9 и MLP 4/4: у каждого Q16 лучше Q8, а Q32 лучше Q16. Это эмпирическое наблюдение на конкретной разметке компонентов/операторе, не общее теоретическое свойство BEACON.

Резко различается целевая точность при разной стоимости: переход Q8→Q16 дал в среднем +24,48 п.п. у ExtraTrees и MLP, а Q16→Q32 — около +27,55 п.п. (ExtraTrees) и +27,60 п.п. (MLP). Таким образом, Q16 — промежуточная **точка кривой Парето**, а не заведомо достаточный бюджет. Q32 вдвое дороже Q16, но на этом эталоне существенно ближе к полному Q36.

У ExtraTrees **254/320** окон имели разделение между третьим и четвёртым эталонными компонентами более `1e-6`. На соответствующих подвыборках среднее по участникам: Q16 66,63%, Q32 96,16%. У MLP все **64/64** окна прошли тот же условный критерий, Q16 67,19%, Q32 94,79%.

**Все семь заданий успешно завершились:** [GitHub Actions — PAMAP2 direct Q-grid](https://github.com/fims9000/BeaconXAI/actions/runs/44648491871). В артефактах для каждой модели и внешнего разбиения содержатся покомпонентные `per_sample.csv`, `per_subject.csv`, `summary.csv`, `reference_windows.csv`, а также `manifest.json` с моделью, списком участников, числом вызовов и контрольной суммой данных. Сырьевой код сравнения: `scripts/run_full_sensitivity_reference.py --q-grid 8,16,32`.

### Нерешённая проверка

Приближение к полному Q36 построено по **той же интерполяционной нейтрализации**, что и Q8/Q16/Q32. Необходимо проверить устойчивость результатов к другому способу вмешательства (например, реальному обучающему образцу конкурирующего класса), а затем оценить время/RAM/энергию на микроконтроллере. Только после этого метод можно позиционировать как физически обоснованное TinyML-объяснение.

## Проверка чувствительности объяснений к оператору вмешательства (UCI HAR)

Критическая проверка: до этого `Q16` сравнивался с `Q36` при **одной и той же интерполяционной нейтрализации**, поэтому высокое совпадение не гарантировало устойчивость к другим разумным операторам. Дополнительно построен второй полный эталон Q36, заменяющий компоненты на сегменты **реального медоида конкурирующего класса из обучающей выборки**. Используется сшивка с плавным переходом на границе (`taper=2`), но это всё ещё синтетическое вмешательство, не доказательство физической допустимости.

На этапе применения выбирается конкурирующий класс как второй класс по оценке **обученной модели**; истинная метка тестового окна не читается. Отдельные тесты проверяют инвариантность результатов при произвольном изменении истинных тестовых меток. Банк прототипов формируется только на обучающих участниках.

| Показатель (top-3 overlap с полным Q36 по реальному медоиду) | ExtraTrees, 64 окна, 9 участников | Raw-input MLP, 32 окна, 9 участников |
| --- | ---: | ---: |
| Полный Q36 по интерполяции **против** полного Q36 по медоиду | 23,15% | 26,85% |
| Q16 по интерполяции против Q36 по медоиду | 23,88% | 29,01% |
| **Q16 по медоиду против Q36 по медоиду** | **69,38%** | **94,44%** |
| Равномерный Q16 по медоиду против Q36 по медоиду | 40,15% | 38,58% |

Все числа в таблице — **макросредние по девяти участникам**. Разбиение проходит через всех девять тестовых участников, но на каждого участника приходится мало окон (по 3–8, в зависимости от квоты); выводы требуют повторения на большем количестве данных. Неоднозначность границы топ-3 у эталона медоида: **16/64** окон ExtraTrees, **0/32** MLP. Указанные числа не являются метриками причинного влияния.

Это **не опровергает** эффективность ранжирования BEACON относительно заданного полного вмешательства: оба Q16 по медоиду существенно лучше случайного Q16. Но **опровергает сильный тезис об устойчивой «истинной» тройке значимых фрагментов**, поскольку два полных эталона при смене оператора имеют лишь ≈23–27% общего состава.

В текущем исследовательском коде `fit_real_donor_bank` хранит средства, медианы, медоиды и донорные примеры; измеренный объём банка — **112 320 байт** для 6 классов UCI HAR. Если при реальной интеграции сохранять только один FP32-медоид каждого класса, только сами шаблоны занимали бы **27 648 байт** (6×128×9×4), без модели и других буферов. Это расчёт памяти шаблонов, не измерение потребления микроконтроллера и не готовая реализация TinyML.

**Все задания успешно выполнены:** [UCI HAR comparison of interpolation and train medoid](https://github.com/fims9000/BeaconXAI/actions/runs/44649240158). Артефакты: `uci-har-operator-extratrees`, `uci-har-operator-raw_mlp`; содержат `per_sample.csv`, `per_subject.csv`, `summary.csv`, `operator_reference_comparison.csv`, `manifest.json` и provenance. Реализация `scripts/run_operator_robustness.py`, тесты `tests/test_operator_robustness.py`, workflow `.github/workflows/uci_har_operator_robustness.yml`.

**Итоговое ограничение статьи:** можно доказывать *устойчивое приближение чувствительности фиксированной black-box модели при заранее определённом операторе вмешательства и ограниченном Q*, но нельзя подменять это устойчивой физической или причинной атрибуцией. Протокол должен явно фиксировать оператор, класс донора, количество запросов и долю неоднозначных полных эталонов.

## Отрицательный результат: два оператора при фиксированном Q16

Разработан отдельный воспроизводимый вариант `beaconxai/dual_operator_audit.py`: из предварительного обучающего ранжирования берутся **8 кандидатов**, каждый оценивается (а) интерполяцией и (б) вставкой реального медоида конкурирующего класса из обучающей выборки. Получается **ровно 16 дополнительных модельных оценок** (а не 16 на каждый оператор), после чего формируется среднее рангов Борда. По умолчанию экспериментальный индикатор `reported` ставится, только если среди трёх первых фрагментов двух операторов совпадают хотя бы два.

Весь выбор, ранги и индикатор отказа вычисляются **без эталонов Q36 и тестовых меток**. Полные эталоны используются только отдельно, при оценке. Кандидатов восемь, тогда как у однооператорных Q16 — шестнадцать: это объективное ограничение разделённого бюджета и важная часть сравнения.

| Совпадение топ-3 в среднем с двумя полными эталонами Q36 | UCI HAR ExtraTrees, 64 окна | UCI HAR raw-input MLP, 32 окна |
| --- | ---: | ---: |
| 16 вызовов только интерполяции | 42,92% | 54,94% |
| 16 вызовов только медоида | 46,69% | 60,03% |
| **8+8 вызовов, объединение двух операторов** | **35,02%** | **46,14%** |

Макроусреднение по 9 тестовым участникам. Разделение бюджета оказалось **хуже обоих однооператорных вариантов**. Несмотря на более широкую интерпретацию вмешательств, оно не улучшает близость к эталонам.

Независимо оценён некаузальный показатель согласованности двух **полных** эталонов: минимум два общих фрагмента в топ-3 и различимая граница 3-го/4-го для обоих. Он получился истинным только на 4/64 окнах ExtraTrees и 3/32 MLP.

| Проверка правила отказа | ExtraTrees | Raw-input MLP |
| --- | ---: | ---: |
| Выдано объяснений (`reported`) | 29/64 | 16/32 |
| Из них согласуются с полными Q36 | 4/29 | 3/16 |
| Выдано объяснений без согласия полных Q36 | 25/29 | 13/16 |

Правило имеет много ложных положительных решений **даже для этого внутреннего критерия**. Следовательно, его нельзя использовать для утверждения «устойчивость подтверждена» или предлагать как готовый механизм селективной достоверности. Даже согласие двух полных эталонов не равно физически корректной причинной атрибуции.

Код: `beaconxai/dual_operator_audit.py`, `beaconxai/dual_operator_metrics.py`, `scripts/run_operator_robustness.py`. Проверки включают точный учёт 16 модельных примеров, изменение истинных тестовых меток без изменения ответа и раздельное макроусреднение по участникам. **Оба задания прошли**, [GitHub Actions — dual-operator robustness](https://github.com/fims9000/BeaconXAI/actions/runs/44650075827). Полные подробности в `dual_operator_per_sample.csv`, `dual_operator_per_subject.csv`, `dual_operator_summary.csv` и `dual_operator_gate.json` артефактов каждого задания.

**Инженерное решение:** не изменять `adaptive_v2` и не включать двухоператорный алгоритм по умолчанию. Этот отрицательный результат важен для статьи, потому что показывает границу применимости простой идеи проверки согласия без независимой достоверной разметки.
