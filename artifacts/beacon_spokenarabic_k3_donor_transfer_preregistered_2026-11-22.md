# BEACON: пререгистрация проверки донорной переносимости K2 vs K3, Q16, SpokenArabicDigits

Дата: **22 ноября 2026**, этот протокол коммитится **до загрузки или анализа официального TEST SpokenArabicDigits**. Корпус не использовался для настройки BEACON. После начала эксперимента не менять критерий успеха, порядок доноров, архитектуру, число компонентов, тестовую выборку, Q или основной парный тест; технические исправления отдельно документировать.

## Корпус, классификатор, качество

**UEA SpokenArabicDigits** в aeon 1.5.0, ожидаемая форма массива: **6599 TRAIN / 2199 TEST**, 13 каналов, 93 отсчёта, 10 классов. Валидировать геометрию и записать SHA архивного NPZ; при несовпадении с опубликованной версией остановиться **до оценки TEST** и отдельно оформить изменение протокола. Это акустические временные признаки произнесённых цифр, не причинно валидный оператор речи.

TRAIN-only стандартизация; фиксированная ExtraTrees из существующего `fit_predictor` (`seed=57`, `trees=120`). Accuracy на полном TEST приводится как описательная диагностика, порог 70% заранее задан; при худшей классификации не корректировать модель по TEST. TEST-метки используются только для финального accuracy, а не для выбора A/B, доноров или маски.

Для сравнения поиска выбрать ровно **320** TEST окон исключительно по индексу: `np.sort(np.random.default_rng(5722).permutation(2199)[:320])`. Список индексов сохраняется в manifest, окон без доноров **не удалять** из знаменателя.

## Донорный банк и заранее определённые роли

TRAIN-only `fit_real_donor_bank`, максимум 16 записей на класс, `seed=67`. Дополнительная классификация каждого TRAIN-донора замороженной моделью оплачивается **offline** и фиксируется отдельно. Для каждого x:
- A = argmax исходного `f(x)`, B = runner-up (не TEST ground truth);
- квалифицированные TRAIN-доноры: только те, для которых `argmax f(D)=B`, с уникальными TRAIN-index;
- фиксируем их порядок по полной нормированной MSE к x, tie-break на исходном TRAIN-index;
- **D1,D2:** два ближайших квалифицированных;
- **D3:** **самый дальний** квалифицированный из оставшихся (стресс-тест); deterministic tie-break TRAIN-index;
- **D4,D5:** два ближайших квалифицированных из оставшихся после удаления D1,D2,D3.

Если квалифицированных меньше пяти, оба метода получают J=0 и 0 онлайн вызовов для данного x; окно остаётся в общем знаменателе 320. Доноры являются **реальными обучающими записями**, но нельзя считать их независимыми людьми/произнесениями по архивным метаданным.

**Важнейшая граница оценки:** D4,D5 не используются ни в выборе маски, ни в онлайн поиске, ни в переранжировании. D3 используется только методом K3. Поэтому для **общей независимой проверки переносимости** сравниваются **только D4,D5**, а не D3.

## Оператор, одна Q и методы

10 непересекающихся временных блоков по всем 13 каналам, `taper=2`, максимальная доля фактически изменённых координат = **35% на каждом проверяемом доноре**. Все методы вызывают **одну и ту же существующую функцию** `search_sparse_robust_counterfactual`, без создания альтернативного ядра:

- `K2` — пул `[D1,D2]`;
- `K3` — пул `[D1,D2,D3]`.

Оба метода получают один и тот же x, исходный f(x), компоненты, target B и TRAIN-class profiles, но `train_profile_donor_gains` пересчитывается для каждого *реально выбранного* набора доноров без модельных вызовов. В обоих случаях **Q=16 дополнительных model-input evaluations суммарно на пул доноров**, включая пробы с отказом и проверки удаления блоков. Никаких отдельных бюджетов для каждого донора. Не выдавать сертификат на основании одного surrogate-score без измерения argmax B на **каждом** онлайн-доноре для одной маски.

**Точная цель K2/K3 не обязана совпадать в размерности донорного сертификата.** Поэтому улучшение K3 в охвате D1+D2 по определению не гарантировано; главный вопрос — перенос той же маски на новых донорах, которых K3 не видел.

## Заранее фиксируемая первичная метрика

После полного завершения каждого поиска и **только если** выдан действительный компактный онлайн-сертификат маски S, отдельно оценить **D4 и D5** той же замороженной моделью. За каждый из двух новых входов начислять **отдельную posthoc стоимость**, исключённую из онлайн Q16 у обоих методов.

`J_fresh(x,method)=1` если (1) в рамках единого Q16 маска S измеренно дала B на всех online-донорах и сохранила редактирование ≤35% на каждом, (2) та же S на обоих **невиденных** D4,D5 дала измеренное B и редактирование ≤35%. Если хотя бы часть отсутствует — J_fresh=0. Это *безусловный охват* среди всех 320 окон, а не процент среди выданных сертификатов.

**Единственная первичная парная гипотеза:** K3 против K2 по `J_fresh` при **общем Q16 и одинаковых D4,D5**, полный N=320. Разница процентных пунктов и двусторонний точный Мак-Немар, alpha=0.05. Если K3 не улучшит безусловный перенос, не объявлять «донорную устойчивость доказанной» на основании conditional transfer rates.

**Вторичные:** онлайн компактный coverage на своих D1,D2(/D3); условный процент D4,D5 transfer среди успехов; локальная 1-deletion минимальность только при фактически проверенных всех единичных удалениях относительно используемого пула; число model queries; среднее время CPU; маски/редактируемые доли; частота отсутствия D1..D5; accuracy модели; SHA и class map. Дополнительная третья стратегия поиска не включена в этот пререгистрированный тест.

## Ограничения научных выводов

Даже успех K3 не означает универсальную устойчивость на популяции, независимых пользователях, другом операторе, физически правдоподобную речь, причинность, SHAP или глобальную минимальность. Offline screening/caching не считаются частью Q, но включаются в общий журнал стоимости. Для K3 третий донор — намеренно дальний, а не случайная выборка; оценивать генерализацию только на D4,D5.

Исследовательские выводы из NATOPS/UWave/PenDigits использовались при постановке вопроса о донорах, но **не** сами данные SpokenArabicDigits. После ознакомления с TEST любые новые варианты будут считаться exploratory и проверяться отдельно.
