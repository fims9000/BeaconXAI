# BEACON — пререгистрация оценки риска переноса донорных контрфактов

22 ноября 2026. **Протокол зафиксирован до загрузки и анализа CharacterTrajectories TEST.** Данные предыдущих экспериментов (SpokenArabicDigits, UWave, PenDigits, NATOPS, Epilepsy, RacketSports) уже просмотрены и не могут считаться новыми holdout.

## Новый архив и замороженная модель

UEA CharacterTrajectories, aeon==1.5.0, equal-length архивный вариант (_eq, через load_equal_length=True). Проверить TRAIN 1422, TEST 1436, 3 канала, 182 отсчета, 20 классов. Источник исходно имеет переменную длину: версия _eq — преобразованные архивом данные, а не сырая запись. При другом формате остановить эксперимент до TEST inference, отдельно документировать технические отклонения.

На TRAIN выполнить детерминированный class-stratified split seed=57: для каждого класса floor(0.70*n) примеров на fit замороженной ExtraTrees; floor(0.15*n) на обучение риск-модели; остальные на независимую калибровку порога. Все три части строго различаются по индексам записей; персональные IDs отсутствуют, независимость авторов/сеансов не установлена. ExtraTrees — существующий fit_predictor, trees=120, seed=57, нормировка и class profiles только по train-fit. Предварительный порог пригодности классификатора: TEST accuracy не ниже 70%; не менять классификатор после просмотра TEST. TEST-метки использовать только для отчета accuracy.

TEST-подвыборка для объяснений: отсортированные первые 320 индексов из np.random.default_rng(5733).permutation(1436). Выбор делается **только по индексам**, не по исходным признакам или меткам. Полные baseline f(x) на 1436 случаях сохранять и учитывать отдельно.

## Доноры и бюджет

A — исходный класс argmax f(x), B — исходный runner-up. Доноры только из train-fit: до 16 окон на класс, seed=67; офлайново подтвердить, что сама модель относит доноров к B. D1,D2 — два ближайших квалифицированных донора по стандартизованной MSE; D3,D4 — два ближайших из остальных; if <4: отказ на этом x для всех политик, сохранить x в знаменателе.

Один существующий поиск search_sparse_robust_counterfactual: 10 последовательных all-channel блоков из 182×3, taper=2, жесткое ограничение максимум 35% реально измененных координат на каждом онлайн доноре. **Единый Q16** для D1+D2, включая все проверки. Сертификат только по измеренным ответам f(T_S(x,D1)), f(T_S(x,D2)) для одной S с argmax=B. Никакого нового копирования поискового ядра.

Проверять эту готовую S на D3 и D4 **только после завершения поиска**. Эти дополнительные model-input evaluations считаются отдельно вне Q16. D3/D4 не участвуют ни в выборе S, ни в вычислении признаков риск-модели. В train-calibration результаты D3/D4 допустимы **только** как обучающие метки риска.

## TRAIN-only риск-модель и порог

На risk-fit примерах, где K2 выдал реальный сертификат, построить ровно 9 признаков: (1) максимальная измеренная support доля среди D1/D2; (2) минимальный измеренный margin целевого класса B среди D1/D2; (3) разброс этих margins; (4) доля выбранных блоков; (5) максимум MSE между x и D1/D2; (6) MSE между D1 и D2; (7) online Q / 16; (8) исходный margin B; (9) бинарный флаг проверенной 1-deletion несократимости. Стандартизировать признаки только по risk-fit.

Целевая метка failure = 1, если готовая S не переносится одновременно на D3 и D4 при том же ограничении измененных координат. LogisticRegression C=1, liblinear, random_state=57; если обучающие outcomes содержат только один класс или не осталось успешных K2, использовать прозрачный constant Laplace estimate без выдуманной модели.

Порог выбирать **только на отдельной gate-calibration части TRAIN**, используя пять порогов, заранее определенных квантилями risk-fit predicted scores [0.10,0.25,0.50,0.75,1.00]. Выбрать самый широкий порог, который принимает минимум 5 масок и имеет одностороннюю Clopper-Pearson верхнюю границу failure-rate с Bonferroni поправкой alpha=0.1/5 **не более 0.50**. Если никакой порог не удовлетворяет — risk-gate отклоняет все объяснения; порог после просмотра TEST не менять. Этот CP bound требует обменяемости калибровочных и будущих случаев, которая архивом по людям не подтверждена: **не заявлять вероятностную гарантию**.

Второй контроль: support-only gate с квотой на gate-calibration, равной числу принятых там risk-gate масок, threshold по support, ties принимать и сообщать. Ни один gate не меняет выбранную K2 маску, не использует D3/D4 при принятии TEST решений и не совершает дополнительных онлайн model calls.

## Конечные метрики на 320 untouched TEST

Сравнить (а) K2 базовый, (б) risk-gate, (в) support-only gate по числу выданных масок / 320, отказам, числу и доле перенесенных на D3+D4 **среди выданных**, и безусловному переносу /320. Для conditional failure вывести интервал Клоппера–Пирсона. Отчет о calib CP bound делать отдельно от TEST interval. Risk-gate лишь отбрасывает готовые маски и **не способен увеличить безусловный абсолютный перенос относительно K2**. Нельзя выводить превосходство на основании одной лишь выросшей conditional success без снижения coverage.

Сохранять per_sample.csv, summary.csv, manifest.json, provenance.txt, модельные коэффициенты/стандартизатор, фиксированные train/cal/test IDs и SHA данных/модели, полную стоимость offline screening, calibration x, онлайн Q16, и posthoc D3/D4 model-input calls. Если модель <70% accuracy, не объявлять исследование доказательством объяснения хорошей модели.

Ограничения: выбранные TRAIN доноры не представляют всех реальных вмешательств; splice не гарантированно допустим физически; классы и персональная независимость не подтверждают причинность; риск-гейт не равнозначен полному многодонорному сертификату; несколько исторических исследований и один новый корпус не доказывают обобщенного преимущества.
