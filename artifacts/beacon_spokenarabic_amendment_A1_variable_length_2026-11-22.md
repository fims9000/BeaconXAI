# Amendment A1: aeon SpokenArabicDigits variable-length input -> normalized-time interpolation

**22 ноября 2026**, внесено после [неудачной попытки скачивания и проверки формы 44953333106](https://github.com/fims9000/BeaconXAI/actions/runs/44953333106), но **до первой модельной оценки, fit модели или расчёта результатов на TEST**.

Протокол [beacon_spokenarabic_k3_donor_transfer_preregistered_2026-11-22.md](beacon_spokenarabic_k3_donor_transfer_preregistered_2026-11-22.md) ожидал UEA SpokenArabicDigits 6599 TRAIN / 2199 TEST, 13 каналов × 93 отсчёта. Официальный loader `aeon.datasets.load_classification` 1.5.0 возвращает 6599 рядов, состоящих из 13 каналов с неодинаковой временной длиной, поэтому `np.asarray(xtr,dtype=np.float32)` выбросил `ValueError: inhomogeneous shape`. **Ни один TEST-model output, классификационная точность, эффект маски или донорная проверка до изменения протокола не вычислялись**.

**Фиксируем отклонение до TEST-эксперимента:** для TRAIN и TEST независимо, без подбора по меткам, каждый канал каждого примера приводится к заранее установленной длине **L=93** линейной интерполяцией на нормированной временной координате ([0,1]):

Для исходной длины 93 сетка тождественна; минимальная исходная длина канала 2, запрет NaN/Inf. Для каждого split отдельно сохранить **исходную длину каждого канала** и SHA получившегося NPZ. Не делать глобальную интерполяцию с использованием другой записи или сведений о TEST-метках.

Это **меняет оператор и популяцию входов по сравнению с сырыми файлами**; выводы будут относиться к нормированно-временным 93-точечным MFCC, не к неопределённым необработанным аудиосигналам. Технический мотив — согласование с заявленной длиной 93 в табличном описании UEA. Факт поправки раскрывается в финальном отчёте, поэтому результат нельзя называть буквально неизменённым исходным протоколом.

**Без изменения**: официальный TRAIN 6599/TEST 2199, класс-кодирование, замороженная ExtraTrees, предварительно выбранные TEST 320 по seed 5722, K2 и K3, роли D1..D5, одинаковая сетка 10 блоков, taper=2, support cap=35%, общая Q16, первичный безусловный перенос D4+D5 и точный Мак-Немар.

После этого amendment никакой дополнительной корректировки по результатам TEST не допускается. Если снова обнаружится несовместимость формы, необходимо отдельно документировать её до выполнения модели, не подбирать параметры без оговорки.
